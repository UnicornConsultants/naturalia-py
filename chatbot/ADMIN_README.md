# B2B 管理後台（第一階段）

入口：http://127.0.0.1:8765/admin

SHOPLINE 是 B2C；我們是獨立 B2B 系統。SHOPLINE 店面只使用客服／導購插件。B2B 帳本、客戶、權限及業務資料不依賴 SHOPLINE。

## 開始使用

1. 啟動 `chatbot/.venv/bin/python chatbot/server.py`。
2. 開啟 `/admin`，自行建立第一位管理員（密碼至少 8 字元）。沒有預設密碼。
3. 建立公司客戶與充值方案；所有資料由零開始。
4. 建立充值申請，填付款方式、流水／收據編號、核款說明及可選附件。
5. 財務／管理員核對實收，填確認金額及原因後批准；本金和贈額一次入帳。
6. 在客戶頁查看有效額度，或帳本頁匯出對帳 CSV。

目前明確標為本機測試帳本；核款操作只改本機資料，不收取／發送任何真實款項。不得把未核實的測試記錄當作正式財務帳。

## WhatsApp 連接

另啟動 `npm start --prefix chatbot/whatsapp`。後台左邊有獨立「WhatsApp 連接」選單：

- 管理員：產生 QR、斷開／重設、切換暫停／草稿／自動回覆。
- 管理員／客服：查看對話、人工接手、確認送出草稿、模擬訊息。
- 財務：不開放 WhatsApp 管理。

原 8767 管理入口轉到此後台；連線服務的 API 不再接受匿名本機管理 nonce。由已登入後台的伺服器透過本機服務密鑰存取。登入後可先執行模擬測試，無須掃碼、不調用 Kimi 或送 WhatsApp。

## 已實作的帳本及權限

- 管理員、財務、客服角色；伺服器端驗權、CSRF、HttpOnly/SameSite Cookie、8 小時登入有效期及登入嘗試限速。
- PBKDF2-HMAC-SHA256 密碼雜湊；不保存明文密碼。
- 公司客戶（第一版一位主要聯絡人）及獨立額度。
- 可版本化充值方案；實收、本金、贈額及各自有效期。修改以新增版本處理，既有申請保留快照。
- PNG/JPEG/PDF 證明附件，5 MB 上限，登入後才能下載。
- 申請待核款／批准／拒絕，人工確認收款及金額一致才能入帳。
- 金額整數分儲存；資料庫交易及唯一約束保證重複或並行批准不會重複入帳。
- 本金與贈額批次分開；客戶頁有效額排除到期批次。
- 入帳分錄及稽核禁止更新／刪除；對帳 CSV 處理公式注入。
- 不讀取網站或 WhatsApp 身份來自動取得帳戶權限。

## 資料及操作範圍

`runtime/b2b.sqlite3` 是獨立 B2B 資料庫，檔案權限 600。`B2B_DB_PATH` 可指定隔離驗收資料庫。測試使用暫存資料庫；主資料庫不預載真實客戶、餘額或方案。

第一版後台沒有公開部署、員工自助重設密碼／停用帳戶、多聯絡人權限、取貨扣款／預留、退款／更正、批次到期分錄、舊帳匯入或客戶自助財務查詢。可用額目前為未到期的充值本金及贈額；帳本匯出列的是歷次入帳，不把到期視作已實作的扣款。

正式多人使用前仍須完成 HTTPS、部署與備份、角色與客戶存取範圍、帳戶生命週期及剩餘財務流程驗收。目前後台僅接受 loopback Host，不應直接轉發上網。

## 驗證

```sh
chatbot/.venv/bin/python -m unittest discover -s chatbot/tests -v
npm test --prefix chatbot/whatsapp
node --check chatbot/static/admin.js
```

本次 30 項 Python 測試及 8 項 WhatsApp 核心測試通過。涵蓋入帳／並行批准、拒絕、角色、金額、到期、不可改寫帳本、CSV、附件、登入、CSRF、來源限制及 WhatsApp 代理。HTTP 實測確認已登入管理員可讀 WhatsApp 狀態，未授權連線接口回 401。

瀏覽器宿主不可用；原生 Chrome 操作亦逾時並偵測到使用者操作，未完成畫面／操作驗收。沒有真實收付款、WhatsApp 發送或付費 Kimi 測試。

### 充值方案編輯與刪除（2026-11-24）
管理員／財務可編輯、停用、重新啟用及刪除充值方案；已刪除方案可從「顯示已刪除方案」還原，還原後維持停用，須另行啟用。畫面不再顯示 v1 等內部版本編號。編輯採用版本檢查避免覆蓋他人的更新；已提交申請和已發出的付款 QR 保留當時方案條款，不隨後續修改／刪除而改變。原有核款及帳本保留。

### 自動核款申請與通知
客人在已綁定帳戶的聊天流程選方案並上載截圖，系統會自動建立申請；頁面標示來源為「聊天截圖自動建立」。手動申請收起為「特殊情況：員工手動補單」。左側核款選單顯示紅點及待審數量，頁面頂部右上角鈴鐺顯示「有人充值，請盡快審核」，可點選申請查看憑證。通知與列表每 5 秒更新，審核完成後移出待審通知。此為後台內通知，不是桌面推播。

通知鈴鐺現位於獨立、固定的全站 header，與頁面內容分開。充值待核款及尚未接手的人工要求合併顯示通知總數；左側「充值申請／核款」與「CS 對話」分別顯示紅點及數量。點擊人工通知會開啟對應對話；接手後從待處理通知移除，對話及操作記錄仍保留。財務角色不取得 CS 通知資料。

### 共用後台資料（2026-11-24 修正）
8765 與 8768 現共用 `runtime/backend-settings.json` 指向的 `runtime/b2b-unified.sqlite3`。已保留兩邊原始資料庫，合併現用帳戶、方案及 WhatsApp CS 訊息。一般啟動不應再給 8768 指定舊 `.cache` 資料庫；`B2B_DB_PATH` 僅供真正隔離的自動測試使用。WhatsApp 連線與 AI 回覆模式分開；暫停只收訊息，草稿要人工確認，自動模式才回覆新私訊。已由 CS 接手的對話須明確交回 AI。

修正：WhatsApp 全渠道暫停 AI 只記錄來訊，不把新客自動標記為等待人工；只有明確要求真人／售後或其他實際轉人工條件才建立接手通知。已接手的對話仍維持人工狀態。

### 對話清單（2026-11-24）
參考 Meetbiz 對話頁，按最後訊息時間倒序；要求人工使用紅色標籤及邊框，不強制舊對話置頂。未讀依每位員工的訊息游標計算，頁面顯示且視窗在前景、讀到訊息底部時才標已讀。讀取只推進到實際載入的訊息 ID，不吞掉稍後抵達的訊息。左選單數字為未讀或待接手的對話數，避免重複計算。電話使用 WhatsApp 來訊的電話 JID、remoteJidAlt 或 Baileys LID 對應；無對應顯示「電話待確認」，不以 LID 假冒電話。顯示電話與綁定 B2B 帳戶分開。

WhatsApp 回覆模式現保存於 `whatsapp/runtime/reply-mode.json`；CS 對話頁顯示實際連線／暫停／草稿／自動模式，不再將未轉人工一律標示「AI 處理中」。2026-11-24 已按用戶測試自動回覆的要求啟用 auto，只處理新來訊，不重播舊訊息。
