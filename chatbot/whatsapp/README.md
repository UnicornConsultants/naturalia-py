# Naturalia WhatsApp 掃碼版本

獨立開發的 WhatsApp 通道，參考 Meetbiz 的掃碼連線方式；不共用其 WhatsApp session、電話號碼、會員或 Agent 程式碼。共用 Naturalia 商品檢索及 Kimi K2.6。

## 啟動與連接

先從專案根目錄啟動 Python 後端，再啟動連線服務：

```sh
chatbot/.venv/bin/python chatbot/server.py
```

另一個終端：

```sh
npm ci --prefix chatbot/whatsapp
npm start --prefix chatbot/whatsapp
```

開啟 http://127.0.0.1:8765/admin ，建立／登入員工帳戶後，進入「WhatsApp 連接」。原本的 http://127.0.0.1:8767 現會轉到後台：

1. 按「產生 QR Code」。
2. 手機 WhatsApp → 已連結裝置 → 連結裝置，掃描 QR Code。
3. 選「產生草稿，人工確認送出」並套用模式。
4. 從另一個 WhatsApp 帳戶發送文字訊息，檢查草稿；按「確認並送出此草稿」才發送。
5. 確認回覆品質後，可自行切換「自動回覆新收到的私訊」。

首次預設為暫停；其後正常重啟會恢復已儲存的模式。手動斷開或連線失效時會儲存暫停。管理介面只監聽本機；不是可公開部署的管理後台。

## 已完成

- QR Code、連線狀態、有限次斷線重連、手動斷開及重設。
- 文字私訊 → 私有後端接口 → 商品 RAG／Kimi → WhatsApp 圖片及文字回覆。
- 商品逐件發送圖片、名稱、參考價及詳情連結；回覆「買 A7K9」選購（短碼以商品提示為準）。商品說明不再附加充值提示。
- 依 WhatsApp 帳戶及對話 ID 分開記錄，後續訊息可沿用上下文。
- 暫停、草稿、明確確認送出、自動回覆、單一對話人工接手。
- 忽略群組、狀態、自己發送的訊息、歷史同步、過舊訊息及未支援媒體；接受 JPEG／PNG 過數截圖。
- 持久化訊息去重、後端回覆快取；送出結果不明時標記待核對，避免自動重發。
- 模擬測試不連 WhatsApp、不呼叫 Kimi、不送訊息，可先測試真實商品檢索。

「人工接手」會暫停該對話 AI，操作員可在 CS 對話工作台直接回覆，亦可交回 AI。尚未提供語音、一般圖片理解或群發。

## 身份與資料

WhatsApp JID 只代表該通道的對話身份，不等於已驗證 SHOPLINE 會員。B2B 身份及帳戶由本系統獨立管理，不以 SHOPLINE 登入作 B2B 授權。可信電話 JID，或 WhatsApp transport 提供的 LID 對應電話，可自動匹配唯一的既有 B2B 帳戶；如該電話未有客戶，自動建立客戶及零餘額充值戶口，毋須人手新增；LID 本身不當作電話，也不信任客人在訊息內自行填寫的電話。同號多帳戶或未取得可信電話時交 CS 處理。人工已接手的對話不會自動恢復 AI。

選購時自動讀取有效餘額（扣除已花費及過期額度），與商品卡相同的售價比較：不足會列出餘額、售價及差額；足夠會列出可用額、扣款額及預計餘額，確認後才扣款。預設直接使用本機商品資料的港幣售價，毋須另設 B2B 售價；如管理員設定個別價格，商品卡與扣款一併使用該價格。已停用或無有效價格的商品才交 CS。充值本金及贈額須審批後才入帳，自動開戶不會新增餘額。

`runtime/auth/` 是 Naturalia 專用登入資料；重設時移到同目錄的 `auth-archive-*`，不永久刪除。這些檔案具有帳戶存取能力，不可分享。`runtime/inbox.sqlite3` 保存對話及回覆；本機操作者可存取，現已接入員工登入及權限；自動保留期尚未加入。

Python `runtime/whatsapp-service.key` 只供本機兩個服務互相驗證；瀏覽器不接觸此 secret 或 Kimi Key。管理操作由 Python 後台驗證員工角色與 CSRF，再透過服務密鑰呼叫連線服務；不要將 8767 port 直接公開至網際網路。

## 驗證及限制

```sh
npm test --prefix chatbot/whatsapp
chatbot/.venv/bin/python -m unittest discover -s chatbot/tests -v
```

- WhatsApp 核心 25 項測試、Python 共 52 項測試通過。
- 整合模擬已完成：真實商品檢索、商品 URL、測試記錄狀態。
- 已掃碼連接，收發文字回覆已有記錄；新增的商品圖片實際手機顯示仍待新入站訊息驗收。
- 本輪未主動使用付費 Kimi 或發送真實 WhatsApp 測試；已在 Chrome 檢索測試 Chat 驗證商品圖片及兩個操作入口。
- Baileys 固定為 `7.0.0-rc14`，Express `4.22.3`；當次 npm audit 無已報告漏洞。Node 24 的 SQLite API 會顯示 experimental 提示。

掃碼連線使用 [Baileys](https://github.com/WhiskeySockets/Baileys)，並非 Meta 官方 Cloud API。正式運營前仍需評估連線穩定性及帳戶使用規範。套件版本已避開官方公布的[訊息偽造漏洞](https://github.com/WhiskeySockets/Baileys/security/advisories/GHSA-qvv5-jq5g-4cgg)。

## 商品圖片及短指令

- 188 件商品圖片來自公開存檔，以 `/product-images/<商品ID>` 提供，只可讀取白名單內的公開圖片。
- WhatsApp 先送說明，再逐件送圖片連文字（最多 3 件）。圖片讀取失敗才退回文字連結；發送結果不明時停止，不重發整組圖片。人工接手亦會停止餘下商品。
- 有意購買：點擊商品詳情連結，或回覆 `詳情 A7K9`。
- 以充值額購買：回覆 `買 A7K9`；買兩件用 `A7K9 2個`，已選定商品可直接回覆 `買兩個`。先顯示商品、單價、數量、總額及預計餘額，回覆 `確認`／`確認購買`／`OK` 才扣款。改數量會重新報價，舊確認失效；重複確認只返回原訂單，不重複扣款。錯誤／過期確認仍提供原商品圖片及選購提示。
- 充值：回覆 `充值`，輸入金額（例如 `500`）後收到 PayMe、Alipay 兩張 QR 圖；回覆付款方式，再上載過數截圖。先傳截圖亦會暫存，確認付款方式後提交核款。支援 `充值 500 PayMe`。自訂金額等額入帳、贈額 0、不設到期；不再列方案。
- 商品碼接受 `RTY6呀`、`買 RTY6 啦`、小寫、標點及引號；疑似多打一個英文字只提示正確短碼，不能猜碼扣款。
- 商品使用固定 4 字母數字短碼，全資料庫唯一，碰撞時重新分配，不使用 I／O／0／1。重啟或換對話不會換碼；仍須在目前對話展示過該商品才能選購。選項保留 7 日，購買報價仍只有效 10 分鐘。已發送的舊數字選項及長 ID 指令保留兼容。
- 本版未實作原生 WhatsApp 互動按鈕。已檢查安裝版本及[上游一般發訊型別](https://github.com/WhiskeySockets/Baileys/blob/master/src/Types/Message.ts)：一般介面包含圖片及按鈕回覆，未提供直接建立互動按鈕的欄位。低階互動封包未經本項目手機端驗證，因此使用圖片、連結及短指令。
