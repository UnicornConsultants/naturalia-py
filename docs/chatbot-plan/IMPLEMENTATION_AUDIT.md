# 實作檢查 — 2026-11-24

## 已修正

1. WhatsApp 先將入站訊息存入 CS，再生成回覆。模型失敗、排隊時轉人工、暫停或重試，都不應遺失客人訊息；同一事件重試不重複寫入。
2. 記錄入站訊息不再受模型生成鎖阻塞。同步失敗會保留本機失敗狀態，人工重試先同步，生成草稿後仍須確認送出。
3. 人工已接手時，客人再提客服／退貨不會重開待接手通知，WhatsApp 亦不會反覆自動發出「等候 CS」訊息。
4. 交回 AI 時，WhatsApp 同步失敗會保留原有人工狀態。手動中斷連線或失效連線的暫停模式會寫入設定；正常程序重啟則保留操作員原先模式。
5. WhatsApp 狀態服務無法使用時，CS 對話頁仍可載入其他渠道及歷史記錄。
6. 移除先按操作時間截取 100 個對話的限制，避免漏掉有新訊息的舊對話，並保留全體待處理計數。列表以最後訊息時間排序；大量對話的分頁與負載測試尚未實施。
7. 訊息 ID 改成不可重用的自增編號，升級時保留原有訊息及已讀位置；清除歷史後新訊息仍會標示未讀。
8. 網站 Chat 的歷史輪詢，若期間已開始送訊息或切換 session，會捨棄過時結果，避免覆蓋送出中的畫面。

## 驗證界線

- 本輪未向真實 WhatsApp 聯絡人主動發訊息，未調用付費 Kimi；手機收到自動回覆仍需新的入站訊息驗收。舊的暫停訊息不會自動補發。
- 網站／測試 Chat 有商品按鈕；目前 WhatsApp 使用商品連結及文字指令操作，並非 WhatsApp 原生互動按鈕。
- LID 並非電話。顯示電話來自 WhatsApp transport 的映射；尚未核實／綁定的 B2B 帳戶仍由 CS 處理，不將客人自行輸入的電話當作身分證明。
- 測試使用臨時資料庫；瀏覽器僅新增測試 Chat 的 `hi`，沒有批准真實核款或執行真實購買。
